### ▶️`models.py`
- Get an idea about the model
- The models:
    - **1 Author** can have **Multiple Books**
```py
class Author(models.Model):
    name = models.CharField(max_length=100)
    bio = models.TextField()

    def __str__(self):
        return self.name


class Book(models.Model):
    author = models.ForeignKey(Author, on_delete=models.CASCADE, related_name='books')
    title = models.CharField(max_length=100)
    published_date = models.DateField()


    def __str__(self):
        return self.title
    
```

# ▶️How can we see using `Serializer Relation`



### 1️⃣`serializers.py`
```py
class AuthorSerializer(serializers.ModelSerializer):
    books = serializers.StringRelatedField(many=True, read_only = True)                   # 👈serializer relation added(StringRelatedField)
    class Meta:
        model = models.Author
        fields = '__all__'


class BookSerializer(serializers.ModelSerializer):
    class Meta:

        model = models.Book
        fields = '__all__'

```


------------

## ✅ Why this works

- Author ↔ Book is a One-to-Many relationship
    - One author can write multiple books.

- related_name='books'
    - Allows Django/DRF to access all books of an author using --> `author.books`


## 📌`StringRelatedField(many=True)`:
- Uses the `__str__()` method of the related Book model
- Returns a read-only list of string values
- Ideal for human-readable output in APIs




--------


## 💡 In one line (memory tip):

- **`StringRelatedField`** shows related objects as readable strings, not full objects or IDs.


-----------------

### ⚠️ Note:
- StringRelatedField is read-only
- You cannot create or update related objects using this field
