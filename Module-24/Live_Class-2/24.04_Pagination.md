-----------------------


### ❔Question is
- Pagination can be done from **Frontend**
- So why do we need pagination on the backend?


-----------------------


## 🔻Reason is
- If I do pagination from frontend
    - All the data will be fetched at a time
- Let's say I have `1,00,000` data in my system
    - whole **100000** data will be fetched
    - The use may need only 50/100 per page 
> This makes the system very slow and heavy


--------------------

## 🧠Solution
- Pagination from backend
- Database returns only required data   
- Frontend Developer just integrates the API
- Sends only the required Request to the backend
- Backend sends a response

# ▶️Pagination Setup

## There are many ways to DRF pagination
- We will use `PageNumberPagination`
- [`Click here`](https://www.django-rest-framework.org/api-guide/pagination/#pagenumberpagination)

### 1️⃣`settings.py`
```py
REST_FRAMEWORK = {
    'DEFAULT_PAGINATION_CLASS': 'rest_framework.pagination.PageNumberPagination',
    'PAGE_SIZE': 3
}
```
>- `PAGE_SIZE` means ---> How many items per page
>- Can change the number of `PAGE_SIZE` ---> 3/5/10/100



### 2️⃣Output
- In the local poject `http://127.0.0.1:8000/api/authors/`
- As `PAGE_SIZE`=3

# ▶️Pagination Setup inside Project

```py
if request.user.is_authenticated and request.user.role == 'teacher':
    queryset = queryset.filter(instructor = request.user)                               # teacher can only see his own created courses


    paginator = PageNumberPagination()
    paginator.page_size = 10
    paginated_queryset = paginator.paginate_queryset(queryset, request)
```
- Lets say we have 100 courses
- Instead of sending 100 courses at once (which would be slow), this block splits the data into pages.
- page_size = 10
    - The API will only return 10 courses at a time.
- paginate_queryset
    - This looks at the ?page=2 query parameter in the URL and slices the database query to get only records 11–20.
